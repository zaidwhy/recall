## Key Decisions

**Project Selection**
- **Recall (photographic memory agent) over other multimodal concepts**: Tackles the hottest unsolved AI problem in 2026 (agent memory), has universal demo appeal ("never lose your keys"), shows full-stack system thinking, and is genuinely novel. Trade-off: more technically ambitious than simpler concepts, but higher recruiter impact ceiling.

**Technical Stack**
- **Gemini Live API over OpenAI Realtime**: "Orders of magnitude cheaper", free tier available, native video+audio+function-calling, ~200ms latency, on-brand with existing Gemini setup (Resume Job-Fit AI project). Trade-off: less mature ecosystem than OpenAI, but cost/capability ratio wins for "as free as possible" goal.
- **ChromaDB (local) for memory store**: Free, persistent, good for embeddings+metadata. Trade-off: single-node only, but sufficient for MVP/demo.
- **FastAPI + Vite/React frontend**: Reuses existing Python patterns, WebSocket support, fast scaffolding from official examples. Trade-off: Python async can be tricky, but familiar territory.

**Architecture**
- **Decoupled ingestion (Flash vision) vs interaction (Live API)**: Critical for staying within free tier. Cheap periodic frame analysis for memory building, expensive Live sessions only when user is actively asking questions. Trade-off: slightly more complexity, but makes the project actually feasible on free tier.
- **Privacy-by-design (local storage, visible toggle, delete controls)**: Addresses obvious "always-watching camera" objection up front, signals maturity to recruiters. Trade-off: adds implementation scope, but necessary for credibility.

**Scope**
- **Flagship 3–6 weeks over quick sprint**: Depth + polish = portfolio anchor piece. Includes eval harness with measurable metrics (recall@k, latency) so it reads industry-grade. Trade-off: longer time investment, but the recruiter ROI justifies it.

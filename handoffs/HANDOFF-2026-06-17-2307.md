### Rate limiting fixes in main.py

- `FLASH_MIN_GAP_S = 120` — 2-minute hard floor between any Flash call (was 30s)
- `FLASH_DAILY_BUDGET = 18` — stops at 18/20 to keep 2 in reserve
- `_flash_calls_today` counter — increments in both ingest loop and analyze handler
- Budget exhaustion: ingest loop sleeps 5 min, analyze handler returns error message
- 429 backoff: parses retry delay from error message, sleeps that long
- Flash call count sent to frontend in `ingested`/`updated` WS messages

### Frontend: flash budget indicator

- `flashCalls` / `flashBudget` state (defaults to 0/18)
- Updated on every `ingested` or `updated` message from backend
- Recording pill shows `· N calls left` when `flashCalls > 0`

## Known constraints / gotchas

- **20 RPD is the hard limit.** At 120s minimum gap, a 40-minute session uses all 20 calls. For a real demo, start recording fresh the day of the demo.
- **Quota resets at midnight** (Google's timezone, likely Pacific). Server restart resets `_flash_calls_today` but not Google's counter.
- **Never enable billing** on this API key — it removes the free tier.
- **GEMINI_VISION_MODEL in .env** overrides the code. If you set it, set it to `gemini-2.5-flash`.
- **Recalled card** was broken (wrong field names). Now fixed — the voice Q&A flow was silently crashing the recalled section.
